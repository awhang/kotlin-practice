# Agent Context - Kotlin Practice Repository

## Project Overview

**Purpose**: A Kotlin practice repository for tech interview preparation and code review practice, focused on enterprise backend systems (not mobile development).

**Goals**:
- Keep Kotlin syntax sharp and familiar
- Practice algorithms, data structures, and design patterns
- Prepare for upcoming tech screen interviews
- Develop code review skills for backend-relevant patterns

## Project Structure

```
kotlin-practice/
├── src/
│   ├── main/kotlin/com/practice/backend/
│   │   ├── algorithms/          # Algorithm implementations
│   │   ├── datastructures/      # Data structure implementations
│   │   ├── designpatterns/      # Enterprise design patterns
│   │   └── problems/            # Toy problems (easy/medium/hard)
│   └── test/kotlin/com/practice/backend/
│       └── [Mirror structure for tests]
├── build.gradle.kts             # Gradle configuration
├── README.md                     # Project documentation
├── PROBLEM_TEMPLATE.kt          # Template for new problems
└── .agent-context.md            # This file

```

## Key Technologies

- **Language**: Kotlin 1.9.21
- **Build Tool**: Gradle
- **Test Framework**: JUnit 5 + Kotest
- **Target JVM**: Java 17
- **Additional**: SLF4J/Logback, Mockito

## Development Workflow

### Building and Testing
```bash
./gradlew build              # Full build
./gradlew test               # Run all tests
./gradlew test --tests "com.practice.backend.problems.easy.*"  # Run specific tests
./gradlew clean              # Clean build artifacts
```

### Creating New Solutions
1. Copy [PROBLEM_TEMPLATE.kt](PROBLEM_TEMPLATE.kt) as a starting point
2. Place implementation in appropriate category (algorithms, problems, etc.)
3. Create mirror test file with `Test` suffix using Kotest
4. Document complexity analysis (time/space) in KDoc comments
5. List edge cases in problem documentation

### Code Review Checklist
- Kotlin idioms and best practices
- Proper null safety handling
- Concurrency/threading considerations
- SOLID principles adherence
- Comprehensive test coverage
- Complexity analysis accuracy

## Session Guidelines

When starting a new session:
1. Review this file for project context
2. Check [README.md](README.md) for structural details
3. Examine sample implementations for code style and patterns
4. Use PROBLEM_TEMPLATE.kt when adding new problems
5. Run `./gradlew test` to verify nothing is broken
6. Maintain test coverage for all new implementations

## Common Tasks

- **Add a new easy problem**: Create file in `src/main/kotlin/com/practice/backend/problems/easy/`, mirror with test
- **Add an algorithm**: Create in `src/main/kotlin/com/practice/backend/algorithms/`, write comprehensive tests
- **Add a data structure**: Create in `src/main/kotlin/com/practice/backend/datastructures/` with full test suite
- **Add a design pattern**: Create in `src/main/kotlin/com/practice/backend/designpatterns/` with example usage

## Notes for Future Sessions

- This project is specifically for backend/server-side patterns, not mobile
- Focus on enterprise-grade code and patterns relevant to tech interviews
- Code review practice is a key goal—write clean, reviewable code
- Always include complexity analysis in documentation
- Use Kotest assertions for consistency and readability
